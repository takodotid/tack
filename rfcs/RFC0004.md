<h1 style="text-align: center;">[RFC#0004] CloudNativePG Support</h1>

# Abstract

The `cnpg` driver switches the primary of a CloudNativePG deployment in the distributed topology: one `Cluster` per site, the primary named by `.spec.replica.primary`, and a demotion token that moves the primary without losing writes. It also moves the read-write `Pooler`, which runs only at the primary's site. This RFC fixes the steps, the signals Tack waits for, and the fields it writes to Git, each with the CloudNativePG fact behind it.

# Overview

| Mode | What happens |
|---|---|
| `Planned` | The old primary demotes and publishes a demotion token. The new site promotes with that token, after replaying up to it. No write is lost. |
| `SiteLoss` | The old site is lost. The new site promotes without a token. The old primary may hold writes the new one lacks; it needs a rebuild before it can follow again. |

# Motivation

Facts from CloudNativePG v1.30.1 source (paths relative to `cloudnative-pg/cloudnative-pg` at tag `v1.30.1`) that shape the requirements:

| Fact | Source | Consequence |
|---|---|---|
| The webhook rejects `promotionToken` while the Cluster is a replica. | `internal/webhook/v1/cluster_webhook.go:2068-2075` | The token and `primary` go in one patch at the new site. |
| Setting `primary` to self without a token promotes at once, with no check. | `api/v1/cluster_funcs.go:1031-1049`, `internal/management/controller/instance_controller.go:1283-1376` | A planned switchover must never set `primary` first. |
| A token together with `minApplyDelay` is rejected. | `cluster_webhook.go:2059-2066` | Plan refuses a planned run when the new site sets `minApplyDelay`. |
| `enabled` together with `primary` is rejected; `enabled` alone is the legacy replica switch. | `cluster_webhook.go:2111-2120` | The driver requires `primary` and refuses `enabled`. |
| `demotionToken` is set once per demotion, before the cleanup that sets `switchReplicaClusterStatus.inProgress` to false; it is cleared whenever the Cluster is not a replica. | `pkg/reconciler/replicaclusterswitch/reconciler.go:130-215`, `internal/controller/cluster_status.go:349-351` | Demotion is complete when the token is set and `inProgress` is not `true`. |
| `lastPromotionToken` is set after `pg_ctl promote` succeeds; it is cleared when the spec token is removed. | `instance_controller.go:1340-1349`, `cluster_status.go:345-347` | Promotion with a token is complete when `lastPromotionToken` equals it. |
| A used token that comes back after removal, or a Cluster recreated with it, fails the timeline check, sets phase `Cluster is unrecoverable and needs manual intervention`, and holds all reconciliation. | `pkg/promotiontoken/promotion_token.go:155-161`, `instance_controller.go:179-197`, `internal/controller/cluster_controller.go:432-443` | Git never holds a token. Tack removes the used token live once promotion is confirmed. |
| An old primary that becomes a replica is never rewound. | `internal/management/controller/instance_startup.go:61-71` | After a site loss, the old primary needs a rebuild. |
| `Pooler.spec.instances: 0` passes validation and sets the Deployment's replicas. | `config/crd/bases/postgresql.cnpg.io_poolers.yaml`, `pkg/specs/pgbouncer/deployments.go:159` | The read-write Pooler is scaled to 0 away from the primary. |
| `Pooler.status.instances` is the Deployment's replicas, not ready pods; its phase is `active` even at 0. | `internal/controller/pooler_status.go:92-118` | Tack waits on the Deployment's `readyReplicas`. |
| In a replica Cluster, the `-rw` Service points at the designated primary, a read-only standby. | `pkg/specs/services.go:132-156` | A Pooler at a replica site would send writes to a standby. |
| The `Cluster` status holds no WAL position or lag. `instancesReportedState` holds only `isPrimary`, `timeLineID` and `ip`. | `api/v1/cluster_types.go:1159-1167` | Tack reads positions from the instance manager. |
| The instance manager serves `/pg/status` on port 8000 without authentication, for the API server's pod proxy, as `kubectl cnpg status` reads it. It holds `receivedLsn`, `replayLsn`, `currentLsn`, `timeLineID`, `systemID`, `isPrimary`, `isWalReceiverActive` and `replayPaused`. It holds no replay time. | `pkg/management/url/url.go:55,79`, `pkg/management/postgres/webserver/remote.go:163-164`, `pkg/postgres/status.go:36-112`, `internal/plugin/resources/instance.go:102-131` | One GET per site, with `get` on `pods/proxy`. |
| The endpoint uses https when the `postgres` container runs with `--status-port-tls`. | `pkg/management/postgres/webserver/client/remote/instance.go:383-399` | Tack reads the Pod first, for the scheme. |
| A replica's `receivedLsn` is never behind its `replayLsn`: the instance manager raises it. | `pkg/management/postgres/probes.go:529-555` | A site's position is the furthest of the two. |
| `timeLineID` comes from the last checkpoint, `pg_control_checkpoint()`. | `pkg/management/postgres/probes.go:539` | Tack shows it, and does not compare sites by it. |
| The replay time, `pg_last_xact_replay_timestamp()`, is only in an optional metrics query, on another port. | `config/manager/default-monitoring.yaml:110-120` | Tack does not read it (Limitations). |

Facts observed on kind with CloudNativePG v1.30.1 and Flux v2.10.0:

| Observation | Consequence |
|---|---|
| During a demotion, `Ready=True` and phase `Cluster in healthy state` come back about a second before `demotionToken` is set. | Health is not a demotion signal; the token and `inProgress` are. |
| `lastPromotionToken` is set up to 2 s before PostgreSQL leaves recovery. | The promotion wait also needs an instance reporting `isPrimary: true` and a healthy phase. |
| A Pooler whose Cluster demotes gives connect timeouts for 7 to 16 s, then read-only errors; a Pooler at 0 gives `Connection refused` at once. | The old site's Pooler goes to 0 before the demotion. |
| A stale token on a Cluster makes the webhook reject Flux's dry-run when Git demotes that Cluster, which blocks the whole Kustomization. | Every patch that declares another primary also sets `promotionToken: null`. |
| An old primary that returns after a site loss keeps taking writes until Flux or Tack fences it, and both sites report healthy. Only the timeline and `isPrimary` differ. | The fence check reads `isPrimary`; routing away from it is Strait's job. |
| A failed-over old primary loops on "requested starting point ... is not in this server's history" while its status stays `Cluster in healthy state`. | Status cannot tell it from a healthy replica; Tack relies on the `Rebuild` follow-up in the ledger. |
| A healthy replica reports its old timeline in `instancesReportedState.*.timeLineID` until its next restartpoint, while it already streams on the new one. | The timeline cannot tell a diverged replica from a healthy one either. |
| Rebuilding needs `bootstrap` changed in Git first: a replica cannot be created from `initdb`. Deleting the Cluster removes its PVC. | The runbook changes Git before deleting. |

| Choice | Reason |
|---|---|
| A Cluster without `spec.replica`, or without `primary`, that reports `isPrimary` is `Primary` (Requirement 3) | Found in a review (#35, row 42): the role table called it `Unknown`, the driver `Primary`. The driver's answer is the safer one: such a site counts as a live primary, so a site-loss plan refuses it (Requirement 5), and the read before its steps stops the run ([RFC#0007] Requirement 6). |
| The plan checks each site's `spec.externalClusters` | Observed on kind in the first three-site e2e (#66): CloudNativePG's webhook refused to make pg-b declare pg-c primary, `spec.replicaCluster.primary: Invalid value: "pg-c": External cluster pg-c not found`, in a step after the promotion. The step stopped with `StepFailed` and changed nothing, but the run stopped with its new primary promoted. |
| Positions from `/pg/status`, through the API server | Decided for #72. SQL needs a database credential and a network path to each site's database, or `exec` into a pod, which Requirement 2 of [RFC#0001] forbids. The status endpoint needs `get` on pods and `pods/proxy` in the member's namespace, and a GET only. |
| A position that cannot be read is a warning | Decided for #72: a site loss must not stop because an operator lacks the new permission, or a pod does not answer. |
| A site's position is the furthest of what it received and replayed | A promotion replays the WAL that a replica received before it ends recovery: received WAL is not lost. |
| A `SiteLoss` run refuses a target behind another replica, unless `--accept-behind` | Found in a review of v1.6.0 (#72): with three sites, nothing helped pick the most caught-up replica, and a replica ahead of `to` was left unable to follow it, with no `Rebuild`. The override is recorded in the ledger, so the read before the first Failover step ([RFC#0009] Requirement 13) accepts it in every process. |
| A `SiteLoss` plan warns of it, and does not refuse | Found in a review of PR #68: the refusal applied to `SiteLoss` plans too, with no override, and said to fix it through Git, which may have gone with the lost site. The step fails closed: CloudNativePG refuses it and it changes nothing, as observed on kind. |

# Requirements

1. Each site's member MUST be one `Cluster` whose `.spec.replica` sets `primary`, and MUST NOT set `enabled`. Each site's `Cluster` MUST have its own name.
2. The driver MUST read, per site: `spec.replica.{self,primary,minApplyDelay,enabled}`, the names of `spec.externalClusters`, `status.phase`, `status.currentPrimary`, `status.switchReplicaClusterStatus.inProgress`, `status.instancesReportedState.*.isPrimary`, the configured `Pooler`, and the position of Requirement 13.
3. Roles, by the first rule that matches. Checked by unit tests.

| Role | Rule |
|---|---|
| `Unknown` | `enabled` is set |
| `Replica` | `primary` is set and differs from `self` (or the name) |
| `Primary` | an instance reports `isPrimary: true`, and `primary` equals `self` (or the name), or `spec.replica` or its `primary` is absent |
| `Unknown` | otherwise |

A site is healthy when its phase is `Cluster in healthy state` and no demotion is in progress.

4. A `Planned` run MUST be refused unless: `from` is a healthy `Primary`; `to` is a healthy `Replica`; every reachable site declares `from`; `to` does not set `minApplyDelay`; no demotion is in progress; and `to` was not left to rebuild by an earlier run ([RFC#0003] Requirement 14). The driver reports the `Cluster`'s `metadata.creationTimestamp` as the member's creation time.
5. A `SiteLoss` run MUST be refused if `from` answers as `Primary`, and unless `to` is a healthy `Replica`.
6. A `Planned` run's Failover steps MUST be, in order:

| # | Step | Site | Content |
|---|---|---|---|
| 1 | Patch, Wait | from | Pooler `instances: 0`; Deployment `replicas` empty |
| 2 | Patch | from | `replica.primary: <to Cluster>`, `replica.promotionToken: null` |
| 3 | Wait | from | `status.demotionToken` not empty, `status.switchReplicaClusterStatus.inProgress` not `true` |
| 4 | Capture | from | `status.demotionToken` as `demotionToken` |
| 5 | Patch | to | `replica.primary: <to Cluster>`, `replica.promotionToken: $(demotionToken)`, in one patch, once the read before the promotion lets it, and from's `status.demotionToken` still equals `$(demotionToken)` when from answers ([RFC#0007] Requirement 9) |
| 6 | Wait | to | `status.lastPromotionToken` equals `$(demotionToken)`, an instance `isPrimary`, phase healthy |
| 7 | Patch | to | `replica.promotionToken: null` |
| 8 | Patch | each other site | `replica.primary: <to Cluster>`, `replica.promotionToken: null` |
| 9 | Patch, Wait | to | Pooler `instances: <configured>`; Deployment `readyReplicas` equals it |
| 10 | Patch, Wait | each site but `from` and `to` | Pooler `instances: 0`; Deployment `replicas` empty |
| 11 | Wait | to | Verify (Requirement 9) |

7. A `SiteLoss` run's Failover steps MUST be, in order:

| # | Step | Site | Content |
|---|---|---|---|
| 1 | Patch | from, deferrable | fence: `replica.primary: <to Cluster>`, `replica.promotionToken: null` |
| 2 | Patch, Wait | from, deferrable | Pooler `instances: 0`; Deployment `replicas` empty |
| 3 | Patch | to | `replica.primary: <to Cluster>`, `replica.promotionToken: null`, once the read before the promotion lets it ([RFC#0007] Requirement 9) |
| 4 | Wait | to | an instance `isPrimary`, phase healthy |
| 5 | Patch | each other site | as Planned step 8 |
| 6 | Patch, Wait | to | as Planned step 9 |
| 7 | Wait | to | Verify (Requirement 9) |

The run MUST record the follow-up `Rebuild` for `from`.

In both modes, `Demotion` ([RFC#0002] Requirement 2) MUST name, by the IDs of every earlier release: `demote-<from>` (Planned step 2) or `fence-<from>` (SiteLoss step 1) for `from`, and `declare-<site>` (Planned step 8, SiteLoss step 5) for each other site but `to`. Checked by unit tests.

8. The Git change MUST set, for every site: the `Cluster`'s `spec.replica.primary` to the `to` Cluster's name; the Pooler's `spec.instances` to the configured value at `to` and `0` elsewhere; and MUST remove the `Cluster`'s `spec.replica.promotionToken`. The removal is optional ([RFC#0006]): without a mapping or find it is left out, and the check before release stops the run if Git sets a token.
9. Verify at `to` MUST hold when the `Cluster` declares itself primary, an instance reports `isPrimary: true`, and the phase is healthy. At any other site it MUST hold when the `Cluster` declares the `to` Cluster primary.
10. Every `Wait` MUST time out: demotion waits after `timeouts.demotion`, promotion and Pooler waits after `timeouts.promotion` (both default 10m).
11. Tack MUST NOT rebuild a member. The rebuild is the operator's: [docs/runbooks/rebuild-old-primary.md](../docs/runbooks/rebuild-old-primary.md).
12. A site that answers, other than `to`, whose `Cluster` does not name `to`'s `Cluster` among its `spec.externalClusters`: every such site's `Cluster` comes to declare it primary, and CloudNativePG refuses a primary that the `Cluster` does not name there. A `Planned` run MUST be refused, in its plan and before any step. A `SiteLoss` plan MUST NOT be refused for it, and MUST note it as a warning that names the step where the run stops, `fence-<from>` before the promotion or `declare-<site>` after it: CloudNativePG refuses that step, which fails, and the run stops there with `StepFailed`. Each message MUST name the site, its `Cluster` and `to`'s. Checked by unit tests.
13. A plan MUST read, at each site that answers, the WAL position of the `Cluster`'s current primary pod (`status.currentPrimary`): a GET of the Pod, then a GET of its instance manager's status, port 8000, path `/pg/status`, through the API server's `pods/proxy`, with the scheme that the Pod's `postgres` container serves. It MUST read nothing else through `pods/proxy`. A read that fails MUST NOT refuse the plan: the plan MUST print it and note it as a warning, which names the permissions. The plan MUST print, per site: for a replica, the received and replayed positions, the timeline, whether its WAL receiver runs and whether replay is paused; for a primary, its write position; and how each replica compares with the others of the same database (`systemID`): `most caught up`, or `behind <site> by <size>`. A site's position is the furthest of its received and replayed positions. A `SiteLoss` plan MUST note that replication between sites is asynchronous, and that the writes the old primary took after `to`'s position are lost; it MUST warn when `to` sets `minApplyDelay`, and when `to`'s replay is paused. Checked by unit tests.
14. A `SiteLoss` run MUST be refused, in its plan and before any step, when a site that answers, other than `from` and `to`, is a `Replica` of the same database whose position is past `to`'s, unless the operator passes `--accept-behind`. The refusal MUST name both sites, both positions, the most caught-up site, and the flag. With the flag, the ledger MUST record it in `spec.acceptBehind`, the plan MUST warn of each such site, and the run MUST record the follow-up `Rebuild` for each. Positions that cannot be read do not refuse. A `Planned` run MUST refuse the flag. Checked by unit tests.

# Design

**Workload.**

```yaml
spec:
  driver: cnpg
  sites:
  - name: a
    kubeContext: site-a
    cnpg:
      cluster: {namespace: db, name: pg-a}
      pooler: {namespace: db, name: pg-a-pooler-rw, instances: 2}
```

**Why the token is removed live.** After step 5 the token has done its work. Left in the spec, it blocks a later demotion (the webhook rejects a token on a replica) and becomes the trap above if it is ever removed and applied again. Removing it from a primary only clears `lastPromotionToken`.

**Why the old Pooler stops first.** Writes stop when the old primary demotes anyway. With its Pooler at 0 first, clients get a fast refusal instead of timeouts and then read-only errors from a standby. The new Pooler comes up once the new primary is healthy.

**Why fence first in a site loss.** If `from` answers at all, it is declared a replica before `to` promotes, so it cannot come back as a second primary. If it does not answer, the fence waits for it ([RFC#0007]).

# Security Considerations

- Requirement 13 needs `get` on `pods` and `pods/proxy` in each member's namespace ([docs/operations.md](../docs/operations.md#permissions), row 18). Pod names are generated, so the grant cannot name them. `pods/proxy` with `get` lets its holder send a GET to any port of any Pod in that namespace through the API server, such as an endpoint served without authentication. Tack sends one GET, to `/pg/status`; grant it only in the members' namespaces.
- `/pg/status` holds positions, the system identifier, configuration hashes and the pod's spec. Tack prints only the positions, the timeline and the stream's state.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| One read-write Pooler per site. Read-only Poolers are not moved. | A workload with several Poolers that follow the primary. |
| With three or more sites, the driver does not check that each replica's `source` chain reaches the new primary. | The first three-site deployment. |
| If the old primary's fast shutdown outlasts `switchoverDelay`, CloudNativePG shuts down immediately and never publishes a token (`pkg/management/postgres/instance.go:695-720`). The demotion wait then times out and the run stops. | An observed timeout. |
| The rebuild of an old primary is manual. | A safe, declarative rebuild in CloudNativePG. |
| The plan does not read when each replica last replayed a transaction: only an optional metrics query of CloudNativePG holds it. A replica whose source stopped long ago reads as most caught up when no other site is ahead. | A replay time in the instance status. |
| Positions are read once in the plan and once after the confirmation. A replica that still restores WAL from an archive can move past another between the read and the promotion. | A replica observed to move after the read. |
| In a `SiteLoss` run, an old primary that is alive but cut off from the operator keeps taking writes until it is fenced ([RFC#0007] Limitations). Those writes are lost to the new primary; the rebuild drops them. | A fence that does not need the site's API. |
