<h1 style="text-align: center;">[RFC#0002] The Engine and the Driver Interface</h1>

# Abstract

Tack is a generic engine plus one driver per workload type. A driver turns the workload's state into steps, as data; the engine adds the hold, the Git change and the checks, and runs the steps in order. This RFC fixes the driver interface, the step types, and the order in which the engine composes a plan.

# Overview

| Engine owns | Driver owns |
|---|---|
| The ledger ([RFC#0003]) | Reading the workload at each site |
| Flux hold, release and checks ([RFC#0005]) | The Failover steps, in order |
| The Git commit ([RFC#0006]) | The fields that make Git equal live |
| Break-glass and deferred steps ([RFC#0007]) | The workload's own word that the switch is complete |
| The routing check ([RFC#0008]) | |
| The dry run ([RFC#0009]) | |

# Motivation

| Choice | Reason |
|---|---|
| Steps are data | A dry run prints exactly what a run does, and a run resumes step by step from the ledger. |
| The engine knows no workload | A second workload type needs a driver, not a second engine. |
| Built-in drivers only | A driver acts on production; it is reviewed like any code. |

# Requirements

1. The engine packages (`internal/engine`, `internal/flux`, `internal/gitops`, `internal/strait`, `internal/cli`) MUST NOT import a driver package, except the binary's wiring and tests. Checked by review of imports.
2. A driver MUST implement:

| Function | Returns | MUST |
|---|---|---|
| `Validate(workload)` | an error | reject a Workload the driver cannot run |
| `Discover(workload, clients)` | per site: reachable, role, declared primary, health, a summary, the objects a run may change, and the member's creation time ([RFC#0003] Requirement 14) | report an unreachable site in its state, not as an error; change nothing |
| `Plan(workload, topology, request)` | the Failover steps, and follow-ups for the operator | refuse a request the topology does not allow, such as a planned switchover from a site that is not a healthy primary |
| `GitChange(workload, topology, request)` | fields, per site and object, with their value after the run | cover every field the Failover steps change that Git sets |
| `Verify(workload, request, site)` | Wait steps | hold only once the switch is complete at that site |

3. A step MUST be one of the types below. A step MUST be safe to run again after it started and was not recorded as done.

| Type | Emitted by | Action | Why it is safe to repeat |
|---|---|---|---|
| `Hold` | engine | annotate one object ([RFC#0005]) | adding an annotation this run set is a no-op |
| `Reconcile` | engine | request a Flux reconcile and wait until handled | a new request is handled like the first |
| `Patch` | driver | JSON merge patch of one live object, field manager `tack` | a merge patch with the same values changes nothing |
| `Wait` | driver | poll conditions on one object until all hold or a timeout | it only reads |
| `Capture` | driver | copy one field of a live object into the ledger | it re-reads the field |
| `Git` | engine | one commit ([RFC#0006]) | a commit this run already pushed is adopted |
| `VerifyGit` | engine | check that Git equals live ([RFC#0005]) | it only reads |
| `Release` | engine | remove the hold | removing what is gone is a no-op |
| `VerifyNoop` | engine | check that Flux changed nothing ([RFC#0005]) | it only reads |
| `Routing` | engine | wait for Strait's route ([RFC#0008]) | it only reads |

4. A `Wait` condition MUST be a JSONPath on the object and one operator: `Equals`, `NotEquals`, `NotEmpty`, `Empty`, or `Contains` (one of the space-separated results equals the value). A missing field reads as empty.
5. A string `$(name)` in a `Patch`, a `Wait` value, a `Reconcile` revision or a Git value MUST be replaced, when the step runs, by the ledger's captured value `name`; `$(git.commit)` by the run's commit. A missing value MUST stop the run with reason `TokenMissing`.
6. The engine MUST compose the plan in this order, and the same inputs MUST give the same plan. Checked by golden tests of the dry run.

| Phase | Steps, in order |
|---|---|
| Hold | per site, in Workload order: `Hold` of each object the run may change, then one `Reconcile` |
| Failover | the driver's steps, as returned |
| PromoteToGitOps | one `Git`, then per site a `Reconcile` until Flux applied the run's commit |
| Release | per site: `VerifyGit`, `Release` of each object, `Reconcile` at the run's commit, `VerifyNoop`; then a `Routing` per Strait service when configured |

7. A step on a site MUST be deferrable unless the site is `to`, or the mode is `Planned` and the site is `from`. A deferrable step on an unreachable site is marked `Deferred` and the run goes on; it runs when the site answers again ([RFC#0007]). A non-deferrable step on an unreachable site MUST stop the run.
8. Step IDs MUST be unique within a plan.

# Design

**Driver interface.** `internal/driver/driver.go`. A driver registers itself by name; the Workload's `spec.driver` selects it. `Discover` returns `Facts`, a string map the driver uses for its own checks in `Plan`.

**Topology.** Each site's state carries a role as the workload reports it:

| Role | Meaning |
|---|---|
| `Primary` | the site's member accepts writes |
| `Replica` | the site's member follows another |
| `Unknown` | the site cannot be read, or its state is neither |

**Plan inputs.** `Compose` takes the request, the topology, the Flux owner of each object, the driver's steps and follow-ups, and the resolved Git changes, and reads nothing. Reading clusters and Git happens before it, in `MakePlan`, which changes nothing.

**Field manager.** Patches use field manager `tack`. [RFC#0005] gives the reason.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| No `exec` step: a command in the workload's own protocol. | The first driver for a workload without a declarative API, such as Valkey. |
| No `generic-crd` driver, configured without code for any operator with a primary field and a status condition. | A second CRD-based workload. |
| `Wait` polls; it does not watch. | Waits that need sub-second reaction. |
