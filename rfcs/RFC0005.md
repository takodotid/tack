<h1 style="text-align: center;">[RFC#0005] Flux Hold and Release</h1>

# Abstract

Flux reapplies Git over live changes. During a run, Tack holds only the objects the run changes, by annotating the live objects so kustomize-controller skips them. Tack releases them only once Git, rendered as Flux renders it, equals live, and then checks that Flux changed nothing.

# Overview

| Phase | Flux work |
|---|---|
| Hold | annotate each object; request a reconcile and wait until handled |
| PromoteToGitOps | after the commit, wait until each site's Kustomization applied it |
| Release | render and diff; remove the annotations; reconcile at the run's commit; check nothing changed |

# Motivation

Facts from Flux v2.10.0 (kustomize-controller v1.10.1, `fluxcd/pkg/ssa` v0.83.0, `fluxcd/pkg/kustomize` v1.44.0):

| Fact | Source | Consequence |
|---|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile: disabled` on the live object (or in Git) makes the controller skip apply, drift correction and prune for that object. | kustomize-controller `internal/controller/kustomization_controller.go:922-925`; ssa `manager_apply.go:688-698` | Annotating live objects is a hold that leaves Git and the Kustomization untouched. |
| A held object still leaves the Kustomization `Ready` and moves `lastAppliedRevision`. | `kustomization_controller.go:562-570` | Ready and the revision do not prove Git equals live for held objects; Tack renders and diffs them itself. |
| The controller applies with field manager `kustomize-controller` and force, and takes over fields of managers named `kubectl*`, `before-first-apply`, or `kustomize-controller` (Update). | `kustomization_controller.go:956-989`; ssa `patch.go:71-80` | Tack writes with its own field manager, `tack`, so a release is not reported as a change. |
| The controller does not watch applied objects; removing the annotation starts nothing. | `kustomization_manager.go:138-170` | Tack requests a reconcile after release. |
| A reconcile request is the annotation `reconcile.fluxcd.io/requestedAt`; `status.lastHandledReconcileAt` equals it once a run that read it ended, on every exit path. | pkg `apis/meta/annotations.go:23`; `kustomization_controller.go:1385-1391` | "Done" also needs Ready=True with reason `ReconciliationSucceeded` and the expected revision. |
| An apply started before the annotation can finish after it. | ssa `manager_apply.go:280-411` | After holding, Tack waits for a fresh reconcile before it patches. |
| helm-controller has no per-object annotation that blocks an upgrade; `helm.toolkit.fluxcd.io/driftDetection: disabled` only skips drift detection. | helm-controller v1.7.1 `internal/action/diff.go:118` | Objects applied by a HelmRelease cannot be held; Tack refuses them. |

# Requirements

1. Hold MUST annotate only the objects the run changes, on the live objects, with `kustomize.toolkit.fluxcd.io/reconcile: disabled` and `failover.tako.id/held-by: <run>`. Tack MUST NOT suspend a Kustomization, and MUST NOT write the annotation to Git.
2. Hold MUST stop the run with `HeldByAnotherRun` if the object is held by another run (other than the one named by `--take-over`), or carries `reconcile: disabled` without a `held-by` of this run. Tack MUST NOT remove a hold it did not set.
3. Hold's write MUST carry the object's `resourceVersion`.
4. Plan MUST refuse an object that no Flux Kustomization applies (no `kustomize.toolkit.fluxcd.io/name` and `/namespace` labels), and an object that a HelmRelease applies (`helm.toolkit.fluxcd.io/name` label).
5. Every live write by Tack MUST use field manager `tack`.
6. After the holds of a site, Tack MUST request a reconcile of the site's Kustomizations (and their GitRepository first) and wait until each is done before any Failover step.
7. A reconcile is done when, for each Kustomization: `status.lastHandledReconcileAt` equals the request, `spec.suspend` is false, `observedGeneration` equals `generation`, Ready is True with reason `ReconciliationSucceeded`, and, when a revision is expected, `status.lastAppliedRevision` names that commit. A suspended Kustomization is skipped: nothing of it is in flight.
8. Before releasing a site, Tack MUST render each held object's Kustomization from the run's commit as kustomize-controller does, and compute a server-side dry-run diff against live as `kustomize-controller`:
   - a held object missing from the render, or any difference on a field the run changed, MUST stop the run with `GitDiffersFromLive`;
   - any other difference MUST stop the run too, unless the operator accepted a Git head during the run ([RFC#0006]); then the differing paths are reported.
9. Release MUST remove both annotations only when `held-by` names this run, and record the object's generation.
10. After release, Tack MUST request a reconcile at the run's commit and then check that each released object's `metadata.generation` is unchanged. A change MUST stop the run with `FluxChanged`, unless the operator accepted a Git head.

# Design

**Render.** `fluxcd/pkg/kustomize`: `NewGenerator(root, kustomization).WriteFile(path)`, `SecureBuild(root, path, false)`, then `SubstituteVariables` per held object when `spec.postBuild` is set, with strict substitution as the controller does by default. `sigs.k8s.io/kustomize/api` and `kyaml` are pinned with a `replace` to the versions kustomize-controller pins, so the render matches.

**Diff.** `fluxcd/pkg/ssa` `ResourceManager.Diff`, without the `reconcile: disabled` exclusion, so held objects are diffed.

**Annotations.**

| Key | Value | Set by |
|---|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile` | `disabled` | Hold |
| `failover.tako.id/held-by` | the run's name | Hold |
| `reconcile.fluxcd.io/requestedAt` | an RFC 3339 time | Reconcile, on the Kustomization and its GitRepository |

# Security Considerations

- Rendering reads the ConfigMaps and Secrets named in a Kustomization's `spec.postBuild.substituteFrom`. A diff message names differing paths, never values, so a substituted secret is never printed.
- Tack needs, per site: `get`, `update`, `patch` on the held kinds; `get`, `patch` on Kustomizations and GitRepositories; `get` on the ConfigMaps and Secrets used for substitution.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| A held object encrypted with SOPS cannot be rendered; Tack does not decrypt. | A held kind that is encrypted. |
| Kustomizations that need remote bases cannot be rendered. | A user with remote bases. |
| Controller flags such as `--override-manager` and feature gates are not read from the cluster; Tack assumes the defaults. | A cluster with non-default flags. |
| Objects applied by a HelmRelease cannot be held. | helm-controller gaining a per-object hold. |
| The check after release compares `generation`, which covers `spec` but not labels or annotations. | A workload whose behaviour depends on metadata. |
