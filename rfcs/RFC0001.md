<h1 style="text-align: center;">[RFC#0001] Scope and Glossary</h1>

# Abstract

Tack moves a stateful workload's primary from one site to another, on the operator's command. This RFC sets Tack's scope, names its parts and defines the terms the other RFCs use.

# Overview

A workload runs at two or more sites, each a Kubernetes cluster. Flux deploys every cluster from one Git repository. One site holds the primary; the others follow it.

In a run, which the operator starts, Tack:

1. stops Flux from applying the objects the run changes (Hold),
2. changes those objects through the workload's own API (Failover),
3. commits the new values to Git (Promote to GitOps),
4. lets Flux apply them again once Git equals live (Release).

Tack records every step in a ledger, the `SiteFailover` resource, before the step starts and after it ends.

# Glossary

| Term | Meaning |
|---|---|
| Operator | The human who decides and starts a run. |
| Site | One Kubernetes cluster that runs a member of the workload. |
| Workload | A stateful service with one primary across sites, such as a CloudNativePG database. Described by a Workload file. |
| Member | The workload's part at one site, such as one CloudNativePG `Cluster`. |
| Primary | The member that accepts writes. |
| Declared primary | The member a site's spec names as primary. |
| Run | One switch of the primary, from the site `from` to the site `to`. |
| Mode | `Planned`: both sites answer, and the old primary hands over. `SiteLoss`: the old site is lost, and the new site promotes without a hand-over. |
| Ledger | The `SiteFailover` object of a run. Its `spec` holds the plan, and its `status` holds what happened. |
| Plan | The ordered list of steps of a run, as data. |
| Step | One action of a plan, such as a patch or a wait. [RFC#0002] lists the types. |
| Driver | The code that knows one workload type's API. It is built into Tack. |
| Engine | The code that runs a plan. It knows nothing about any workload. |
| Hold | Annotating a live object so Flux stops applying it ([RFC#0005]). |
| Release | Removing the hold ([RFC#0005]). |
| Fence | Making a member that should not be primary declare the new primary, so it stops being primary. |
| Demotion token | The value a CloudNativePG primary publishes when it demotes. The new primary promotes with it, without losing writes ([RFC#0004]). |
| Break-glass | A run that switches the live clusters while Git is unreachable, then commits once Git is back ([RFC#0007]). |
| Strait | A separate project that points each application name at the active member. Tack reads its status ([RFC#0008]). |

# Motivation

Moving a CloudNativePG primary between sites by hand fails in two ways:

| Failure | Cause |
|---|---|
| Flux reverts the switch | Flux applies the old values from Git over the live change. |
| The switch loses writes or needs a rebuild | The demotion token must pass from one cluster to the other between two steps. Promoting without it forks the data. |

Tack makes both safe and records them.

| Choice | Reason |
|---|---|
| Only a GET of the instance manager's status through a pod's proxy | No Kubernetes object holds a member's WAL position. SQL would need a database credential or `exec`. The status endpoint only reads. |
| Tests of the code's structure check each requirement | Review alone does not stop a later change from breaking one. |

# Requirements

1. Tack MUST start a run only from the operator's `tack run` command. No other code path creates a `SiteFailover`. Checked by `TestOnlyTackRunStartsARun`.
2. Tack MUST change a workload only through its declarative API, such as a CloudNativePG `Cluster` spec. It MUST NOT exec into pods, edit files or touch data. The only request through a pod's proxy is a GET by the `cnpg` driver: port 8000, `/pg/status`, for a member's WAL position; port 9187, `/metrics`, for a replica's replay lag ([RFC#0004] Requirement 13). Only the Git package ([RFC#0006]) runs a program, `git`. Checked by `TestNoExec`.
3. Tack MUST NOT create, update or delete any Strait object. Checked by `TestStraitIsOnlyRead` and `TestReaderOnlyGets` ([RFC#0008]).
4. Tack MUST NOT decide to fail over: no timer, watch or health trigger starts a run. The test covers Tack's own packages, not dependencies. Checked by `TestOnlyTackRunStartsARun` and `TestNoTrigger`.
5. Drivers MUST be built into the `tack` binary. Tack MUST NOT load a driver from outside; a driver acts on production. Checked by `TestDriversAreBuiltIn`.
6. Tack MUST be written in Go. Checked by `TestWrittenInGo`.

# Design

| Part | Role | RFC |
|---|---|---|
| `tack` CLI | The operator's commands: `plan`, `run`, `resume`, `status`. | [RFC#0009] |
| Engine and drivers | The engine plans and runs steps. Drivers supply the workload's steps. | [RFC#0002] |
| Ledger | `SiteFailover`: its schema, its phases, and how a run resumes. | [RFC#0003] |
| `cnpg` driver | CloudNativePG in its distributed topology. | [RFC#0004] |
| Flux hold and release | Keep Flux from undoing the switch, and check afterwards that Flux changes nothing. | [RFC#0005] |
| Git change | One commit that makes Git equal live. | [RFC#0006] |
| Break-glass | Switch the live clusters while Git cannot be reached. | [RFC#0007] |
| Routing check | Confirm Strait routes to the new primary. | [RFC#0008] |

Language: Go. It fits client-go and the Flux and CloudNativePG APIs, and builds static binaries.

# Implementation

| Path | Content |
|---|---|
| `cmd/tack` | The binary. |
| `api/v1` | The `SiteFailover` types; the CRD is generated from them. |
| `internal/engine` | Plan composition and the runner. |
| `internal/driver` | The driver interface; `internal/driver/cnpg` the v1 driver. |
| `internal/flux`, `internal/gitops`, `internal/strait` | Hold and release, the Git change, the routing check. |
| `internal/cli` | The commands, the skill document and the man pages. |
| `internal/scope/scope_test.go` | Requirements 1 to 6, from the syntax and types of the `cmd/tack` packages (`golang.org/x/tools/go/packages`, test files left out): `TestOnlyTackRunStartsARun`, `TestNoExec`, `TestStraitIsOnlyRead`, `TestNoTrigger`, `TestDriversAreBuiltIn`, `TestWrittenInGo` |
| `internal/strait/strait_test.go` | Requirement 3: `TestReaderOnlyGets` |

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| No controller. A run lasts as long as the `tack` process and resumes from the ledger. | A controller that runs the same ledger. |
