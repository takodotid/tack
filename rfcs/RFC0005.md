<h1 style="text-align: center;">[RFC#0005] Flux Hold and Release</h1>

# Abstract

Flux reapplies Git over live changes. During a run, Tack holds only the objects the run changes, by annotating the live objects so kustomize-controller skips them. Tack releases them only once Git, rendered as Flux renders it, equals live, and then checks that Flux changed nothing.

# Overview

| Phase | Flux work |
|---|---|
| Hold | annotate each object; request a reconcile and wait until handled |
| PromoteToGitOps | after the commit, wait until each site's Kustomization applied it |
| Release | render and diff; remove the annotations; reconcile at the run's commit; check nothing changed |

# Motivation

Facts from Flux v2.10.0 (kustomize-controller v1.10.1, `fluxcd/pkg/ssa` v0.83.0, `fluxcd/pkg/kustomize` v1.44.0):

| Fact | Source | Consequence |
|---|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile: disabled` on the live object (or in Git) makes the controller skip apply, drift correction and prune for that object. | kustomize-controller `internal/controller/kustomization_controller.go:922-925`; ssa `manager_apply.go:688-698` | Annotating live objects is a hold that leaves Git and the Kustomization untouched. |
| A held object still leaves the Kustomization `Ready` and moves `lastAppliedRevision`. | `kustomization_controller.go:562-570` | Ready and the revision do not prove Git equals live for held objects; Tack renders and diffs them itself. |
| The controller applies with field manager `kustomize-controller` and force, and takes over fields of managers named `kubectl*`, `before-first-apply`, or `kustomize-controller` (Update). | `kustomization_controller.go:956-989`; ssa `patch.go:71-80` | Tack writes with its own field manager, `tack`, so a release is not reported as a change. |
| The controller does not watch applied objects; removing the annotation starts nothing. | `kustomization_manager.go:138-170` | Tack requests a reconcile after release. |
| A reconcile request is the annotation `reconcile.fluxcd.io/requestedAt`; `status.lastHandledReconcileAt` equals it once a run that read it ended, on every exit path. | pkg `apis/meta/annotations.go:23`; `kustomization_controller.go:1385-1391` | "Done" also needs Ready=True with reason `ReconciliationSucceeded` and the expected revision. |
| An apply started before the annotation can finish after it. | ssa `manager_apply.go:280-411` | After holding, Tack waits for a fresh reconcile before it patches. |
| `kustomize.toolkit.fluxcd.io/ssa`: `Ignore` (Git or live) skips the object like `reconcile: disabled`; `IfNotPresent` (Git only) skips it when it exists; `Merge` (Git or live) still applies with force and only keeps fields of `kubectl*` managers. | `kustomization_controller.go:922-928`, `:1021-1023`; ssa `manager_apply.go:578`, `:700-703` | `Merge` does not stop a revert, and `IfNotPresent` is read from Git only. `Ignore` would work, but `reconcile: disabled` is the documented hold and names its intent. |
| helm-controller has no per-object annotation that blocks an upgrade; `helm.toolkit.fluxcd.io/driftDetection: disabled` only skips drift detection. | helm-controller v1.7.1 `internal/action/diff.go:118` | Objects applied by a HelmRelease cannot be held; Tack refuses them. |
| A `Reconcile` after the run's commit waits for the branch head | Found in a review (#29), the mechanism verified in a unit test: the steps waited for the exact commit of the run. A commit pushed on top of it before Flux applied it made the wait time out on every resume, and `--accept-git-head` could not change what it waited for. A commit pushed after the check before release made the wait after release time out, so the check that Flux changed nothing never ran. Flux applies the head of the branch, not the run's commit. |
| The check before release runs in the process that releases | Found in a review (#35, row 16) and reproduced in a unit test: a release that failed after `VerifyGit` succeeded left the next `tack resume` releasing without a check, possibly hours later. A commit pushed between the two processes went unchecked, and Flux applied it once the site was released. |
| A diff message prints the values of the run's own fields | Found in a review (#35, row 40): this RFC said a diff message names paths, never values, while the check printed Git's and live's values for the fields the run changed. Those values tell the operator what to fix in Git. The fields are the driver's, and a value substituted from a Secret is masked. |
| The generation is recorded before the hold is removed | Found in a review (#35, row 36) and reproduced in a unit test: a process died after it removed a hold, before the ledger recorded the release, and Flux changed the object in between. The next process found no hold, recorded the new generation, and the check after release passed. While the run holds the object, Flux cannot change it. |
| A patch reads the hold first | Found in a review (#27): a patch read nothing before it changed an object, so only the search for ledgers could stop a run that another run took over, and that search misses a ledger at a site that does not answer. The hold is on the object itself. |

# Requirements

1. Hold MUST annotate only the objects the run changes, on the live objects, with `kustomize.toolkit.fluxcd.io/reconcile: disabled` and `failover.tako.id/held-by: <run>`. Tack MUST NOT suspend a Kustomization, and MUST NOT write the annotation to Git.
2. Hold MUST stop the run with `HeldByAnotherRun` if the object is held by another run (other than the one the run takes over, `spec.takeOver` ([RFC#0003] Requirement 17)), or carries `reconcile: disabled` without a `held-by` of this run. Tack MUST NOT remove a hold it did not set.
3. Hold's write MUST carry the object's `resourceVersion`.
4. Plan MUST refuse an object that no Flux Kustomization applies (no `kustomize.toolkit.fluxcd.io/name` and `/namespace` labels), and an object that a HelmRelease applies (`helm.toolkit.fluxcd.io/name` label).
5. Every live write by Tack MUST use field manager `tack`.
6. After the holds of a site, Tack MUST request a reconcile of the site's Kustomizations (and their GitRepository first, except in a `SiteLoss` run: [RFC#0007] Requirement 1) and wait until each is done before any Failover step.
7. A reconcile is done when, for each Kustomization: `status.lastHandledReconcileAt` equals the request, `spec.suspend` is false, `observedGeneration` equals `generation`, Ready is True with reason `ReconciliationSucceeded`, and, when a revision is expected, `status.lastAppliedRevision` names that commit. A suspended Kustomization is skipped: nothing of it is in flight.
8. Before releasing a site, in the process that releases it, Tack MUST stop with `GitChanged` when the branch head is not the release revision: the run's commit, or the head the operator accepted after it ([RFC#0006] Requirement 10). Flux applies the head once the objects are released. When the site's `VerifyGit` step succeeded in an earlier process, Tack MUST run it again before the site's first Release step that is not `Succeeded`, and record it in the ledger. Checked by unit tests. Tack MUST then render each held object's Kustomization from the release revision as kustomize-controller does, and compute a server-side dry-run diff against live as `kustomize-controller`:
   - the render MUST read a copy of the checkout filtered by source-controller's rules (`.sourceignore`, `spec.ignore`, the default patterns, no symlinks), and MUST refuse a Kustomization whose source is not a GitRepository, or a GitRepository with `spec.include`;
   - a held object missing from the render, or one the dry-run would create, MUST stop the run with `GitDiffersFromLive`;
   - each field the run changed MUST be compared directly, Git value against live value: after Tack's patch the field belongs to field manager `tack`, so a Git that leaves it out shows no drift in the dry-run. A difference, or a path found in neither, MUST stop the run with `GitDiffersFromLive`;
   - any other difference MUST stop the run too, unless the operator accepted a Git head during the run ([RFC#0006]); then the differing paths are reported.
9. Release MUST remove both annotations only when `held-by` names this run. Before it removes them, it MUST record the object's generation in the ledger, from the read that the removal's update carries the `resourceVersion` of; when that write fails, the hold MUST stay. A Release step that finds the hold already gone MUST keep a generation recorded before, and record the one it reads only when there is none. Checked by unit tests.
10. After release, Tack MUST request a reconcile at the release revision, or the branch head that contains it (Requirement 12). It MUST then wait, up to `timeouts.flux`, until each released object's Kustomization is Ready=True with reason `ReconciliationSucceeded`, and fail the step when one is Ready=False or the wait times out. Only then MUST it check that each released object's `metadata.generation` is unchanged and that no hold is back on it. Checked by unit tests. A changed generation MUST stop the run with `FluxChanged`, unless the operator accepted a Git head. The run's fields are all under `spec`, so an unchanged generation means Flux left them as they were.
11. Before a `Patch` of an object the run holds, Tack MUST read the object's hold, and stop when it does not name the run: with `HeldByAnotherRun` when another run holds it, and `StepFailed` when it is not held. Checked by unit tests.
12. A `Reconcile` after the run's commit MUST fetch the branch, and wait until Flux applied its head when the head contains the release revision; it MUST stop with `GitChanged` when the head does not contain it. Checked by unit tests.

# Design

**Render.** `fluxcd/pkg/kustomize`: `NewGenerator(root, kustomization).WriteFile(path)` in a filtered copy of the checkout, `SecureBuild(root, path, false)`, then `SubstituteVariables` on every resource when `spec.postBuild` is set (variables may appear in names), with strict substitution as the controller does by default. Variables are loaded once per Kustomization. `sigs.k8s.io/kustomize/api` and `kyaml` are pinned with a `replace` to the versions kustomize-controller pins, so the render matches.

**Diff.** `fluxcd/pkg/ssa` `ResourceManager.Diff`, without the `reconcile: disabled` exclusion, so held objects are diffed.

**Annotations.**

| Key | Value | Set by |
|---|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile` | `disabled` | Hold |
| `failover.tako.id/held-by` | the run's name | Hold |
| `reconcile.fluxcd.io/requestedAt` | an RFC 3339 time | Reconcile, on the Kustomization, and on its GitRepository when the step fetches Git |

# Security Considerations

- Rendering reads the ConfigMaps and Secrets named in a Kustomization's `spec.postBuild.substituteFrom`. A diff message names the differing paths. It prints Git's and live's values only for the fields the run changed, which the driver names ([RFC#0002] `GitChange`), so the operator can fix Git: in them, each value of a variable substituted from a Secret is replaced by `*****`, no value of a `Secret` object is printed, and a captured value is named, not printed ([RFC#0009] Requirement 10). Any other differing path is named without its values. Checked by unit tests.
- Tack needs, per site: `get`, `update`, `patch` on the held kinds; `get`, `patch` on Kustomizations and GitRepositories; `get` on the ConfigMaps and Secrets used for substitution.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| A held object encrypted with SOPS cannot be rendered; Tack does not decrypt. | A held kind that is encrypted. |
| Kustomizations that need remote bases cannot be rendered. | A user with remote bases. |
| Controller flags such as `--override-manager` and feature gates are not read from the cluster; Tack assumes the defaults. | A cluster with non-default flags. |
| Objects applied by a HelmRelease cannot be held. | helm-controller gaining a per-object hold. |
| An object that carries `kustomize.toolkit.fluxcd.io/ssa: IfNotPresent` in Git is diffed as if Flux applied it. Flux leaves it alone once it exists, so the check may stop a run that Flux would not disturb. | A held object with that annotation. |
| The check after release compares `generation`, which covers `spec` but not labels or annotations. | A workload whose behaviour depends on metadata. |
| Strict substitution is assumed, as the controller's default feature gate sets it. | A cluster with the gate off. |
| The direct field comparison is on raw JSON; a value the API server rewrites into a canonical form, such as a quantity, reads as a difference. | A run that changes such a field. |
| With remote bases disallowed, kustomize may still try to fetch a remote resource before failing, from the operator's machine. | A user with remote resources. |
