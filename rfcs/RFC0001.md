<h1 style="text-align: center;">[RFC#0001] Scope and Glossary</h1>

# Abstract

Tack moves a stateful workload's primary from one site to another, on the operator's command. This RFC sets what Tack does and does not do, names its parts, and defines the terms the other RFCs use.

# Overview

A workload runs at two or more sites. Each site has its own Kubernetes cluster, deployed by Flux from one Git repository. One site holds the workload's primary; the others follow it.

Tack takes a run from the operator, and for that run:

1. stops Flux from applying the objects the run changes (Hold),
2. changes those objects through the workload's own API (Failover),
3. commits the new values to Git (Promote to GitOps),
4. lets Flux apply them again once Git equals live (Release).

Every step is recorded in a ledger, the `SiteFailover` resource, before it starts and after it ends.

# Glossary

| Term | Meaning |
|---|---|
| Operator | The human who decides and starts a run. |
| Site | One Kubernetes cluster that runs a member of the workload. |
| Workload | A stateful service with one primary across sites, such as a CloudNativePG database. Described by a Workload file. |
| Member | The workload's part at one site, such as one CloudNativePG `Cluster`. |
| Primary | The member that accepts writes. |
| Declared primary | The member a site's spec names as primary. |
| Run | One switch of the primary, from the site `from` to the site `to`. |
| Mode | `Planned`: both sites answer; the old primary hands over. `SiteLoss`: the old site is lost; the new site promotes without a hand-over. |
| Ledger | The `SiteFailover` object of a run: its plan in `spec`, what happened in `status`. |
| Plan | The ordered list of steps of a run, as data. |
| Step | One action of a plan, such as a patch or a wait. [RFC#0002] lists the types. |
| Driver | The code that knows one workload type's API. Built into Tack. |
| Engine | The code that runs a plan. It knows no workload. |
| Hold | Annotating a live object so Flux stops applying it. [RFC#0005]. |
| Release | Removing the hold. [RFC#0005]. |
| Fence | Making a member that should not be primary declare the new primary, so it stops being primary. |
| Demotion token | The value a CloudNativePG primary publishes when it demotes; the new primary uses it to promote without losing writes. [RFC#0004]. |
| Break-glass | A run that switches live while Git cannot be reached, and commits once Git is back. [RFC#0007]. |
| Strait | A separate project that points each application name at the active member. Tack reads its status. [RFC#0008]. |

# Motivation

Moving a CloudNativePG primary between sites by hand fails in two ways:

| Failure | Cause |
|---|---|
| Flux reverts the switch | Flux applies the old values from Git over the live change. |
| The switch loses writes or needs a rebuild | The demotion token must travel from one cluster to the other between two steps; promoting without it forks the data. |

Tack exists to make these two steps safe and recorded.

| Choice | Reason |
|---|---|
| Each requirement is checked by a test of the code's structure | Found in a review (#35, row 58): every requirement rested on review alone. A grep confirmed each then; nothing kept a later change from breaking one. |

# Requirements

1. Tack MUST start a run only from the operator's `tack run` command. No other code path creates a `SiteFailover`. Checked by the unit test `TestOnlyTackRunStartsARun`: only the `run` command refers to the engine's `Start`, no interface in Tack's code declares a method with its signature, and the only calls that can create a `SiteFailover` are the ledger's create, which only `Start` reaches.
2. Tack MUST change a workload only through the workload's own declarative API, such as a CloudNativePG `Cluster` spec. It MUST NOT exec into pods, edit files, or touch data. Checked by the unit test `TestNoExec`: the step types are those of [RFC#0002] Requirement 3; the binary links none of client-go's transports that exec into a pod, attach to one or forward its port; the only subresource the code names is `status`; and only the Git package ([RFC#0006]) runs a program, `git`.
3. Tack MUST NOT create, update or delete any Strait object. Checked by the unit tests `TestStraitIsOnlyRead`, which finds no client call but `Get` in the Strait reader ([RFC#0008]) and Strait's API group named nowhere else in the binary, and `TestReaderOnlyGets`, which runs the reader with a client that fails on any other call.
4. Tack MUST NOT decide to fail over. It has no timer, no watch and no health trigger that starts a run. Checked by the unit tests `TestOnlyTackRunStartsARun` and `TestNoTrigger`: no package of Tack's module imports an informer, a watch, a cache or a controller runtime, and none calls `Watch`. Dependencies, such as controller-runtime's client, bring client-go's informers and cache into the binary; the test covers Tack's own code.
5. Drivers MUST be built into the `tack` binary. Tack MUST NOT load a driver from outside, since a driver acts on production. Checked by the unit test `TestDriversAreBuiltIn`: only the `init` of a package under `internal/driver` registers a driver, `cmd/tack` imports each, and no package of the module imports Go's `plugin` package.
6. Tack MUST be written in Go. Checked by the unit test `TestWrittenInGo`: no package of the module in the binary has a C, C++ or assembly file, or imports `"C"`, also behind a build constraint.

# Design

| Part | Role | RFC |
|---|---|---|
| `tack` CLI | The operator's commands: `plan`, `run`, `resume`, `status`. | [RFC#0009] |
| Engine and drivers | Plan and run steps; drivers supply the workload's steps. | [RFC#0002] |
| Ledger | `SiteFailover`, its schema, phases and resume. | [RFC#0003] |
| `cnpg` driver | CloudNativePG in its distributed topology. | [RFC#0004] |
| Flux hold and release | Keep Flux from undoing the switch, and check it changes nothing after. | [RFC#0005] |
| Git change | One commit that makes Git equal live. | [RFC#0006] |
| Break-glass | Switch live while Git is unreachable. | [RFC#0007] |
| Routing check | Confirm Strait routes to the new primary. | [RFC#0008] |

**Language.** Go: it is the simplest fit for client-go, Flux's and CloudNativePG's APIs, and builds static binaries.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| No controller. A run lives as long as the `tack` process, and resumes from the ledger. | A controller that runs the same ledger. |
| One workload per run. | A need to switch several workloads together. |
| One driver in v1: `cnpg`. | A second workload type, such as Valkey. |
| The binary links kustomize's plugin loader, the only package of its dependencies that imports Go's `plugin`. Flux's build, which Tack's render uses, turns kustomize's plugins off, and the release builds without cgo, where Go's `plugin.Open` is not implemented. `TestDriversAreBuiltIn` fails if another package imports `plugin`. | A dependency that loads code at run time. |
| The structure tests read the code, not what it does at run time: a `SiteFailover` created as an unstructured object, or passed to a client as a `client.Object` variable, or a Strait object written through a client that another package builds, would pass them. Review covers that. | A change that writes objects through another kind of client. |
