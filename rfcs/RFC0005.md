<h1 style="text-align: center;">[RFC#0005] Flux Hold and Release</h1>

# Abstract

Flux applies Git over live changes. During a run, Tack holds the objects the run changes by annotating them, releases them once Git (rendered as Flux renders it) equals live, then checks that Flux changed nothing.

# Overview

| Phase | Flux work |
|---|---|
| Hold | annotate each object; request a reconcile and wait until handled |
| PromoteToGitOps | after the commit, wait until each site's Kustomization applied it |
| Release | render and diff; remove the annotations; reconcile at the run's commit; check nothing changed |

# Motivation

Flux v2.10.0 ([References](#references)):

| Fact | Consequence |
|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile: disabled` on a live object makes the controller skip apply, drift correction and prune for it. | Annotating live objects holds them; Git and the Kustomization stay untouched. |
| A held object still leaves the Kustomization `Ready` and moves `lastAppliedRevision`. | Neither proves Git equals live. Tack renders and diffs the held objects itself. |
| The controller applies with field manager `kustomize-controller` and force, and takes over fields of managers `kubectl*`, `before-first-apply` and `kustomize-controller`. | Tack writes as `tack`, so a release is not reported as a change. |
| The controller does not watch applied objects; removing the annotation starts nothing. | Tack requests a reconcile after release. |
| A reconcile request is the annotation `reconcile.fluxcd.io/requestedAt`; `status.lastHandledReconcileAt` equals it once a run that read it ended. | Done also needs Ready=True, reason `ReconciliationSucceeded`, and the expected revision. |
| An apply started before the annotation can finish after it. | After holding, Tack waits for a fresh reconcile before patching. |
| `kustomize.toolkit.fluxcd.io/ssa`: `Ignore` skips the object like `reconcile: disabled`; `IfNotPresent` (Git only) skips it when it exists; `Merge` still applies with force. | `Merge` does not stop a revert; `IfNotPresent` is read from Git only. `reconcile: disabled` is the documented hold. |
| helm-controller has no per-object annotation that blocks an upgrade. | Tack refuses objects a HelmRelease applies. |

Choices of Tack:

| Choice | Reason |
|---|---|
| A `Reconcile` after the run's commit waits for the branch head | Flux applies the branch head. Waiting for the exact commit timed out when a later commit landed first. |
| The check before release runs in the releasing process | After a failed release, the next `tack resume` could release unchecked, hours later. |
| A diff message prints the values of the run's own fields | They tell the operator what to fix in Git. A value substituted from a Secret is masked. |
| A suspended Kustomization fails the check after release | It keeps the Ready=True of its last reconcile while Flux applies nothing. |
| The generation is recorded before the hold is removed | A process that died between the two left Flux free to change the object unseen. |
| A patch reads the hold first | The search for ledgers misses a site that does not answer; the hold is on the object. |

# Requirements

1. Hold MUST annotate only the objects the run changes, on the live objects, with `kustomize.toolkit.fluxcd.io/reconcile: disabled` and `failover.tako.id/held-by: <run>`. Tack MUST NOT suspend a Kustomization, and MUST NOT write the annotation to Git.
2. Hold MUST stop the run with `HeldByAnotherRun` when the object is held by another run, or carries `reconcile: disabled` without a `held-by` of this run. A run named in `spec.takeOver` or `spec.takeOvers` ([RFC#0003] Requirement 17) is not another run. Tack MUST NOT remove a hold it did not set.
3. Hold's write MUST carry the object's `resourceVersion`.
4. Plan MUST refuse an object that no Flux Kustomization applies (no `kustomize.toolkit.fluxcd.io/name` and `/namespace` labels), and an object that a HelmRelease applies (`helm.toolkit.fluxcd.io/name` label).
5. Every live write by Tack MUST use field manager `tack`.
6. After the holds of a site, Tack MUST request a reconcile of the site's Kustomizations (after their GitRepository's, except in a `SiteLoss` run: [RFC#0007] Requirement 1) and wait until each is done before any Failover step.
7. A reconcile is done when, for each Kustomization: `status.lastHandledReconcileAt` equals the request, `spec.suspend` is false, `observedGeneration` equals `generation`, Ready is True with reason `ReconciliationSucceeded`, and, when a revision is expected, `status.lastAppliedRevision` names that commit. A suspended Kustomization is skipped.
8. Before releasing a site, in the releasing process, Tack MUST stop with `GitChanged` when the branch head is not the release revision: the run's commit, or the head the operator accepted after it ([RFC#0006] Requirement 10). When the site's `VerifyGit` step succeeded in an earlier process, Tack MUST run it again before the site's first Release step that is not `Succeeded`, and record it in the ledger. Checked by unit tests. Tack MUST then render each held object's Kustomization from the release revision as kustomize-controller does, and compute a server-side dry-run diff against live as `kustomize-controller`:
   - the render MUST read a copy of the checkout filtered by source-controller's rules (`.sourceignore`, `spec.ignore`, default patterns, no symlinks), and MUST refuse a Kustomization whose source is not a GitRepository, or a GitRepository with `spec.include`;
   - a held object missing from the render, or one the dry-run would create, MUST stop the run with `GitDiffersFromLive`;
   - each field the run changed MUST be compared directly, Git value against live value (after Tack's patch the field belongs to `tack`, so a field Git omits shows no drift in the dry-run). A difference, or a path found in neither, MUST stop the run with `GitDiffersFromLive`;
   - any other difference MUST stop the run too, unless the operator accepted a Git head during the run ([RFC#0006]); the differing paths are then reported.
9. Release MUST remove both annotations only when `held-by` names this run. Before that, it MUST record the object's generation in the ledger, from the same read whose `resourceVersion` the removal carries. When the ledger write fails, the hold MUST stay. A Release step that finds the hold already gone MUST keep a generation recorded before, and record the one it reads only when there is none. Checked by unit tests.
10. After release, Tack MUST request a reconcile at the release revision, or the branch head that contains it (Requirement 12). It MUST then wait, up to `timeouts.flux`, until each released object's Kustomization is Ready=True with reason `ReconciliationSucceeded`, and fail the step when one is Ready=False or the wait times out. A Kustomization with `spec.suspend` set MUST fail the step at once, with a message that names it. Only then MUST Tack check that each released object's `metadata.generation` is unchanged and that no hold is back. Checked by unit tests. A changed generation MUST stop the run with `FluxChanged`, unless the operator accepted a Git head. The run's fields are all under `spec`, so an unchanged generation means Flux left them as they were.
11. Before a `Patch` of an object the run holds, Tack MUST read the object's hold, and stop when it does not name the run: with `HeldByAnotherRun` when another run holds it, and `StepFailed` when it is not held. Checked by unit tests.
12. A `Reconcile` after the run's commit MUST fetch the branch, and wait until Flux applied its head when the head contains the release revision; it MUST stop with `GitChanged` when the head does not contain it. Checked by unit tests.

# Design

**Render.** Tack renders with `fluxcd/pkg/kustomize` in a filtered copy of the checkout: `NewGenerator(root, kustomization).WriteFile(path)`, then `SecureBuild(root, path, false)`. When `spec.postBuild` is set, it runs `SubstituteVariables` on every resource, since variables may appear in names. Substitution is strict, as in the controller. Variables load once per Kustomization. A `replace` pins `sigs.k8s.io/kustomize/api` and `kyaml` to kustomize-controller's versions, so the render matches.

**Diff.** Tack diffs with `fluxcd/pkg/ssa` `ResourceManager.Diff`, without the `reconcile: disabled` exclusion, so held objects are diffed.

**Annotations.**

| Key | Value | Set by |
|---|---|---|
| `kustomize.toolkit.fluxcd.io/reconcile` | `disabled` | Hold |
| `failover.tako.id/held-by` | the run's name | Hold |
| `reconcile.fluxcd.io/requestedAt` | an RFC 3339 time | Reconcile, on the Kustomization, and on its GitRepository when the step fetches Git |

# Security Considerations

- Rendering reads the ConfigMaps and Secrets in a Kustomization's `spec.postBuild.substituteFrom`. A diff message prints values only for the fields the run changed ([RFC#0002] `GitChange`), with each value from a Secret replaced by `*****`. It prints no value of a `Secret` object, and names a captured value without printing it ([RFC#0009] Requirement 10). Checked by unit tests.
- Tack needs, per site: `get`, `update`, `patch` on the held kinds; `get`, `patch` on Kustomizations and GitRepositories; `get` on the ConfigMaps and Secrets used for substitution.

# Limitations

| Limitation | Trigger to revisit |
|---|---|
| A held object encrypted with SOPS cannot be rendered. Tack does not decrypt. | A held kind that is encrypted. |
| Kustomizations that need remote bases cannot be rendered. | A user with remote bases. |
| Tack does not read controller flags (such as `--override-manager`) or feature gates. It assumes the defaults, including strict substitution. | A cluster with other flags or gates. |
| Objects applied by a HelmRelease cannot be held. | helm-controller gaining a per-object hold. |
| An object with `kustomize.toolkit.fluxcd.io/ssa: IfNotPresent` in Git is diffed as if Flux applied it, so the check may stop a run Flux would not disturb. | A held object with that annotation. |
| The check after release compares `generation`, which covers `spec` but not labels or annotations. | A workload whose behaviour depends on metadata. |
| The direct field comparison is on raw JSON. A value the API server rewrites to a canonical form, such as a quantity, reads as a difference. | A run that changes such a field. |
| With remote bases disallowed, kustomize may still try to fetch a remote resource from the operator's machine before it fails. | A user with remote resources. |
