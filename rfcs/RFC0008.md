<h1 style="text-align: center;">[RFC#0008] Confirming Routing from Strait's Status</h1>

# Abstract

Strait routes each application name to the workload's active member, and follows a promotion on its own. When the Workload names Strait's objects, the last thing a run does is wait until Strait, at each listed site, routes to the new primary's member only. Tack reads Strait's status. It never writes Strait's objects.

# Overview

The check is optional. A plan has it only when the Workload sets `spec.routing.strait`.

# Requirements

1. Tack MUST only `get` Strait's `SiteService` objects (`strait.tako.id/v1`, served by Strait v1.0.0 and later). Checked by the unit tests `TestReaderOnlyGets`, whose client fails on any call but `Get`, and `TestStraitIsOnlyRead` ([RFC#0001] Requirement 3).
2. The Workload MUST name, per site that runs Strait, the `SiteService` to read, and, for every site, the name of the site's member in that `SiteService`.
3. A `Routing` step MUST succeed when the `SiteService`'s `status.observedGeneration` equals its `metadata.generation`, `status.route.members` is exactly the `to` site's member, and `status.route.reason` is `Active`. It MUST fail after `timeouts.routing` (default 2m).
4. When a site does not serve `SiteService` `strait.tako.id/v1`, the step MUST fail saying that Strait v1.0.0 or later is not installed there.
5. The `Routing` steps MUST run after every release.

# Design

```yaml
spec:
  routing:
    strait:
      services:
      - {site: a, namespace: apps, name: postgres}
      - {site: b, namespace: apps, name: postgres}
      members:
      - {site: a, member: pg-a}
      - {site: b, member: pg-b}
```

Tack reads these fields, as Strait's `api/v1/siteservice_types.go` defines them at commit `036aa99e8171` (Strait v1.0.0):

| Field | Use |
|---|---|
| `metadata.generation`, `status.observedGeneration` | equal when the status is current |
| `status.route.members` | the members Strait routes to; empty means it routes nowhere |
| `status.route.reason` | `Active` when Strait routes to one writable member |
| `status.route.message` | reported when the check fails |

During a switchover, Strait's route goes through the reasons `DeclarationsDisagree` and `Transitioning`, with no members, before it reaches `Active`. Each site's controller reconciles within 2 s. A remote site follows within the `Site`'s `exchange.peerTimeout`, 6 s by default. So the step does not read the status once: it polls until both the member and `Active` match, for up to `timeouts.routing`.
